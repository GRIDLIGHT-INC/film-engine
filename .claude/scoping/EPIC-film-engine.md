# Epic: Film Engine — Full Production Pipeline

## Overview

Transform Gridlight into an **AI film production house** where users write stories, manage production, and generate all assets (video, voice, music, sound design) to produce editor-ready output. Gridlight orchestrates specialized agents across the full pipeline: screenplay → pre-production → storyboard → voice/dialogue → video generation → lip-sync → sound design → post-production → NLE export.

## Business Goals

- **Expand Gridlight into creative production** — the "virtual film studio" vision
- **End-to-end pipeline**: From story text to timeline-ready media, no external tools required until final edit
- **Leverage existing infrastructure**: Agent orchestration, Neo4j continuity graph, TTS plumbing, image gen (GRD-32)
- **Creator-first**: Output formats editors actually use (ProRes, FCPXML, EDL, markers)
- **Differentiator**: Not just generating clips — managing entire productions with continuity, character consistency, and reproducibility

## Constraints

- **VRAM-heavy**: Video diffusion (SVD/AnimateDiff) needs 12-24GB, competes with LLM/image/3D agents
- **Multi-step pipelines**: Each shot = 4-6 agent handoffs (keyframe → video → voice → lipsync → post)
- **Model maturity**: Video diffusion models produce 2-5s clips; longer sequences need stitching
- **No existing video/film code**: Starting from zero (TTS gateway plumbing exists, image gen 60-70% on GRD-32)
- **Temporal coherence**: Maintaining character/scene consistency across shots is an unsolved hard problem
- **Audio sync**: Lip-sync quality degrades on plosives/sibilants; needs viseme-level alignment

  |                                                        |
  +--[Scene Card YAML]---> POST /film/shots/generate ---> Gateway
  |                                                        |
  +--[Storyboard]--------> POST /film/storyboard -------> Gateway
                                                           |
                                                    PipelineScheduler

              |            |            |            |            |            |
              v            v            v            v            v            v

          (SDXL)     (AnimateDiff) (Qwen3-TTS)  (SadTalker) (MusicGen)  (CodeFormer)

### New Agent Roles

```rust
pub enum AgentRole {
    Infer,        // LLM inference (existing)
    Embed,        // Embedding (existing)
    Rerank,       // Reranking (existing)
    Verify,       // Verification (existing)
    ImageGen,     // Image diffusion (from image gen epic)
    Gen3D,        // 3D generation (from 3D epic)
    MeshProcess,  // Mesh processing (from 3D epic)
    VideoGen,     // Video diffusion — GPU-heavy (AnimateDiff, SVD, CogVideoX)
    VoiceGen,     // TTS & voice cloning — GPU or CPU (Qwen3-TTS, XTTS v2)
    LipSync,      // Lip synchronization — GPU (SadTalker, Wav2Lip)
    AudioGen,     // Music & SFX generation — GPU (MusicGen, AudioCraft)
    PostProcess,  // Face restore, upscale, color — GPU/CPU (CodeFormer, ESRGAN)
}
```

### Pipeline Per Shot

```
1. ImageGen → keyframe(s) from prompt + camera + lighting params
2. VideoGen → animate keyframe into 2-5s clip
3. VoiceGen → generate dialogue audio from text + voice profile
4. LipSync  → sync character mouth to dialogue audio
5. AudioGen → ambient/score/SFX for the shot (optional)
6. PostProcess → face restore, upscale, film grain, color match
7. Assemble → merge video + audio tracks, write metadata sidecar
```

## Key Decisions

| # | Decision | Choice | Rationale |
|---|----------|--------|-----------|
| 1 | Video model (MVP) | **AnimateDiff + SDXL** | Open source, builds on image gen agent, 12GB VRAM, 2-5s clips |
| 2 | TTS model | **Qwen3-TTS** primary, XTTS v2 fallback | Already scoped in EPIC-voice-tts; Apache-2.0; voice cloning |
| 3 | Lip-sync model | **SadTalker** primary, Wav2Lip fallback | Open source, audio-driven, viseme-aware |
| 4 | Music generation | **MusicGen (Meta)** | MIT license, text-to-music, melody conditioning, 30s clips |
| 5 | Post-processing | **CodeFormer + Real-ESRGAN** | Face restoration + upscaling; open source |
| 6 | Scene description | **YAML Scene Cards** | Human-readable, version-controllable, editor-friendly |
| 7 | NLE export format | **FCPXML primary, EDL secondary** | FCPXML carries markers/metadata; EDL is universal fallback |
| 8 | Edit codecs | **ProRes 422 LT** (mac), **DNxHR LB** (win) | NLE-native, fast scrubbing; H.264 for previews |
| 9 | Continuity tracking | **Neo4j graph** | Already running; natural fit for relationships |
| 10 | Reproducibility | **Render ledger in PostgreSQL** | Full parameter capture; locked/creative modes |
| 11 | Job model | **Async (job_id + SSE)** | Shots take 30-120s; SSE for real-time progress |

### Total VRAM for Pipelines

| Scenario | VRAM Needed | Notes |
|----------|-------------|-------|
| Single shot (time-shared) | 16 GB | Models load/unload sequentially |
| Parallel voice+video | 24 GB or 2x 12 GB | Video on GPU0, voice+lipsync on GPU1 |
| Full production pipeline | 2x 24 GB | Dedicated GPU per heavy model |
| All features + LLM | 3x 24 GB or 2x 48 GB | Separate GPUs for inference, video, audio |

### Latency Budgets (per 5s shot)

| Step | Target | Fallback |
|------|--------|----------|
| Keyframe generation | < 10s | Lower resolution |
| Video generation | < 45s | Fewer frames, lower res |
| Voice synthesis | < 5s per line | CPU fallback |
| Lip-sync | < 20s | Wav2Lip (faster) |
| Music/SFX | < 30s per 30s clip | Shorter generation |
| Post-processing | < 15s | Skip face restore |
| **Total per shot** | **< 120s** | **< 180s degraded** |

### Implementation Notes

- **Architecture adapted**: The original epic assumed a Rust gateway + separate Python agent containers. The actual implementation uses a vanilla Node.js HTTP server (`backend/server.js`) with SQLite (`better-sqlite3`) instead of PostgreSQL/Neo4j. All agent-facing routes (Phases 4-7, 9, 12) are implemented as HTTP proxy routes that forward to the Gridlight platform via `lib/gridlight-client.js`.
- **Neo4j replaced**: Continuity checking (FILM-016, FILM-075) uses SQLite queries instead of a graph database, which is sufficient for the single-node architecture.
- **Desktop app → Web SPA**: Phase 11 was built as a vanilla JS frontend in `src/index.html` rather than Tauri/React desktop components.
- **Request queuing (FILM-034)**: Implemented as a per-endpoint semaphore in `gridlight-client.js` with 429 retry + exponential backoff, rather than per-agent Python asyncio semaphores.
- **Project Bundle (Export/Import)**: Added beyond the original epic scope — `.tar.gz` archive bundling with full ID remapping for project portability.
- **456 tests**: 413 unit tests + 43 integration tests, all passing via `node --test`.
