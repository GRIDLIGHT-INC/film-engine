## P2-1 · The character sheet has no column protection, and cannot get any
`src/index.html` — `characterSheetHtml` | architectural debt | **HIGH**

Measured `ssSection(...)` calls per renderer: **character 0**, location 10,
prop 9. `ssSection` is what emits `data-region`, and `data-region` is the
identity the column tests key on. So one of three sheets sits outside the
shared region abstraction and the protection built by this work covers two of
three *by construction*.

Mutation-proven: moving `cs-palette` to the other column leaves **74/74
passing**. This is the sheet the original complaint named — *"sections aren't
organized properly on all three"*.

**Fix:** route `characterSheetHtml`'s regions through `ssSection`, then add
`CHARACTER_LAYOUT` and call `columnsOf('characterSheetHtml', 'cs', …)`. One
mechanism for three sheets rather than a third idiom.

## P2-2 · A modal rule now polices nothing
`backend/tests/page-handlers.test.js:185` | coverage debt | **HIGH**

*"every modal is shown with the class its own CSS displays"* scans for inline
`getElementById(x).classList.add(y)`. Measured: **35** overlays in the markup,
**0** inline calls remaining, **49** `showModal()` call sites. It iterates an
empty set and passes.

This is the same defect class this branch fixed in `shot-anchor` — an assertion
coupled to a call *shape* — except that one failed loudly and got repaired,
while this one fails **silently**. A real modal regression would ship.

**Fix:** follow the helper, exactly as `shot-anchor.test.js` now does — derive
the display class from the stylesheet, accept inline **or** helper, and verify
the helper actually adds that class. That template is already written and
mutation-proven.

## P2-3 · A location field bypasses `ssField` and stays editable in view mode
`src/index.html:25276` | incomplete mode handling | **MEDIUM**

`renderLocationSheet` renders
`<textarea class="ss-input" rows="4" data-field="section_${sec.id}">` directly
rather than through `ssField`, so a set description is editable on a sheet that
opens read-only, and it sits outside the one helper carrying the escaping and
mode contract. The prop sheet has **zero** such controls and a test now pins
that.

**Deliberately not fixed here.** `plan.md` puts the location sheet explicitly
out of scope, and this branch carries a containment test whose whole purpose is
to fail if the prop change leaks into that sheet — editing it would defeat the
guard.

**Fix:** replace with an `ssField('section_' + sec.id, …)` call once the
location sheet is in scope.

## P2-4 · Ids reach `on*=` attributes without the attribute-safe helper
`src/index.html` — prop 5 sites, location 6, character 9 | hardening | **LOW**

`onclick="openSubjectSheet('location','${loc.id}')"` and 19 similar sites
interpolate ids and loop indices raw, while `jsAttr()` — added specifically
because `JSON.stringify`'s double quotes once broke an `onclick` attribute —
sits unused at `src/index.html:28542`.

**Not exploitable today**, and that was verified rather than assumed: ids are
`crypto.randomUUID()`, no route reads an id from a request body, and bundle
import remaps them. It is defence-in-depth, and it earns a place here only
because the helper already exists.

**Fix:** route id interpolations through `jsAttr()`. Do it as a **set over all
20 sites**, not the one that was noticed — the value is removing the class, and
a fix applied to one sheet leaves the other two looking safe.
