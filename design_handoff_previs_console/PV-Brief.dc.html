Build brief · for Claude Code

Previs console — see the real set, lock the decisions

Rebuild #page-previs as a no-scroll console: the camera view as large as the window allows, a movement timeline under it, and a tabbed panel on the right. Add splat rendering so the view shows the real world, a plan view, rendered Explore thumbnails, and a Decisions strip that makes Apply / Lock visible — and carries it into Production. Confirm every route path before calling it.

1 · Layout (no page scroll)

  • Main panel padding 0. Header 52 + Decisions strip 44 · body = view column + 360px right panel.
  • View column: camera view (flex) + timeline 150. At 1440 the view is 816×560; at 1920 ≈1290×730 (today 665×375).
  • The in-page Shots column goes: shots move to the phase side panel (PvSidePanel) with thumbnails and decision state; Plan pages become compact pills above them.
  • Remove the inner bordered frame; the header row's lone New World joins the side panel.
  • Lighting / Body & Rig / Plate & Output / Advanced move into the Scene tab.

2 · View modes — one camera, five ways to see it

  • Look — Gaussian splats (Spark on three.js, as the previz handoff intends). 100k tier while moving, 500k when still, full for plate stills.
  • Geometry — today's collider render; label it "what generation receives". Plates keep rendering from the collider.
  • Depth — collider depth, near light / far dark.
  • Plan — top-down from the collider: walls, counter, booths, cast marks, every camera as a cone; drag a cone to move the camera.
  • 360° — the stored panorama on a sphere, look-around only.
  • Picture-in-picture bottom-right: the plan in camera modes, the camera in Plan mode.

3 · Splats — what has to change in the backend

  • lib/world-assets.js copies collider, panorama, thumbnail and only records splat_100k / splat_500k / splat_full by URL, "because nothing can display them until WORLD_SPLATS is switched on". Switch it on and copy splat_100k + splat_500k on first open (≈6.7 MB per world); fetch splat_full only when a still is rendered.
  • Serve them like the collider (GET /film/world-versions/:vid/…), with the same scale_factor applied so splats and collider line up and every measurement stays true.
  • Vendor the renderer inline like three.js r149 already is (build.target: single-html).
  • Walk mode: WASD at eye height, collider as the collision volume. S saves the current camera as a setup.

4 · Decisions — Trying → Applied → Locked, and on to Production

○ Trying
The previs workspace differs from the scene card. Nothing downstream sees it.
Apply →
✓ Applied
Written to the scene card — the one record image and video payloads read.
Lock →
● Locked
Approved fingerprint stored; world version pinned. Production can't overwrite it.
→
Production
Shot drawer "From Previs" lists each locked decision; the prompt parts it fills are read-only.
  • Decisions and their payloads already exist in lib/decision-contract.js: shot.camera, shot.direction, shot.lighting, shot.location_view (Set view), shot.characters (Cast), shot.props. Movement is video-only by design (see its EXCEPTIONS).
  • State per chip = compare applicationFingerprints(row, card): staged ≠ card → Trying; equal → Applied; equal and matches approved_fingerprint → Locked.
  • Apply: POST /film/shots/:id/previs/apply. Lock shot: POST /film/shots/:id/previs/approve + pin the world version (world_pin_shot).
  • New: per-decision lock. Today approval fingerprints the whole blocking; store one fingerprint per decision id so the lens can be locked while lighting is still being tried.
  • Changing a locked decision requires Unlock; the shot then shows as stale (existing "approved, then changed" rule) in Previs, the side panel, the Production node and before any paid run.
